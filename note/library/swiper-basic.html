Swiper Basic

프레임의 한계를 넘어 무한한 공간을 탐색하게 만드는 슬라이드 라이브러리

소개

정보량이 많은 프로젝트에서 모든 콘텐츠를 세로로만 나열할 경우 페이지가 지나치게 길어져 사용자가 느끼는 시각적 피로도가 높아질 수 있다고 생각했습니다.

한정된 섹션 안에서 가로 공간을 효율적으로 활용할 수 있는 Swiper를 사용하여 다양한 정보를 사용자가 이탈하지 않고 끝까지 몰입할 수 있는 레이아웃을 설계하고자 했습니다.

예제 화면

프로젝트에 사용했던 Swiper-Basic 효과 데모가 준비되어 있습니다.

예제 코드

slidesPerView

화면 너비에 따른 슬라이드 노출을 소수점 단위로 조정하여 다음 콘텐츠의 일부를 의도적으로 노출 함으로써 스와이퍼 액션을 유도했습니다.

loop

콘텐츠의 시작과 끝을 무한 루프로 설계하여 사용자가 어느 방향으로 탐색하더라도 흐름이 끊기지 않는 연속성을 구현했습니다.

breakpoints

사용자의 접속 환경에 따라 카드 수와 간격을 재구성하여 어떤 디바이스에서도 균형을 유지하도록 설계했습니다.

autoplay

가만히 있어도 슬라이드가 부드럽게 넘어가며 시선을 끌어주고 사용자가 손을 대는 순간에는 멈춰서 집중하게 만들어줍니다. 

const swiper = new Swiper(".mySwiper", {
  slidesPerView: 1.2,
  spaceBetween: 20,
  loop: true,
  autoplay: { delay: 3000 },
  navigation: {
    nextEl: ".swiper-next-btn",
    prevEl: ".swiper-prev-btn",
  },
  pagination: {
    el: ".swiper-pagination",
    clickable: true,
  },
  breakpoints: {
    640: {
      slidesPerView: 2.2,
      spaceBetween: 30,
    },
    1024: {
      slidesPerView: 3.2,
      spaceBetween: 40,
    },
  },
});

비교 분석

CSS만으로는 슬라이드가 끝없이 이어지는 무한 루프를 구현하거나 화면 크기에 맞춰 노출 개수를 정밀하게 제어하는 데 어려움이 있습니다. Swiper는 복잡한 코드를 직접 짤 필요 없이 설정만으로 첫 페이지와 마지막을 자연스럽게 연결해 줄 수 있고 breakpoints 설계를 통해 어떤 화면에서도 의도한 슬라이드 비율을 일정하게 해줍니다.

slidesPerView의 소수점 수치를 미세하게 조정하며 다음 카드가 살짝 노출되는 효과가 사용자로 하여금 자연스럽게 다음 콘텐츠를 탐색하고 싶게 만드는 흐름을 만든다고 생각합니다.

주요 학습 포인트

slidesPerView를 auto나 특정 수치로 설정할 때 라이브러리가 슬라이드의 너비와 높이를 인라인 스타일로 강제 계산하는 과정에서 기존 CSS와 충돌이 잦았습니다. 특히 슬라이드 간의 간격이나 크기가 의도한 대로 제어되지 않을 때 !important를 활용해 스타일 우선순위를 강제로 확보하며 해결했습니다. 이를 통해 라이브러리가 편리함을 제공하지만 때로는 개발자가 명시적으로 스타일 제어권을 가져와야 하는 상황이 발생한다는 것을 배웠습니다.

기본적으로 제공되는 Navigation이나 Pagination의 디자인이 프로젝트의 전체적인 톤과 맞지 않아 CSS로 완전히 새롭게 재설계하기도 했습니다. 라이브러리가 제공하는 기본 클래스명을 찾아내어 하나하나 커스텀 디자인을 입히는 과정을 통해 완성도 높은 UI를 위해서는 라이브러리의 기능을 그대로 쓰는 것에 그치지 않고 서비스의 색깔에 맞게 변형하는 능력이 중요하다는 점을 느꼈습니다.

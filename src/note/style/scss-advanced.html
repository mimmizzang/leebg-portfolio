SCSS @mixin, Map & List

재사용 가능한 로직 설계와 데이터를 활용한 스타일 자동화

소개

단순히 스타일 값을 변수에 담아 재사용하는 수준을 넘어 자주 사용되는 디자인 패턴을 하나의 독립된 기능으로 정의하고 필요할 때마다 호출해 사용하는 도구 중심의 설계가 필요했습니다. 스타일 코드를 효율적으로 통합 관리하기 위해 CSS의 한계를 넘어 조건과 데이터에 따라 스타일이 결정되는 로직을 SCSS의 심화 기능으로 구현했습니다.

재사용 가능한 @mixin과 복합적인 디자인 규격을 체계화하는 Map & List를 결합하여 스타일의 정의와 실행을 분리했습니다. 이를 통해 직접적인 코드 수정 없이 데이터 변경만으로 스타일 전체를 제어할 수 있는 유연한 환경을 만들고자 했습니다.

@mixin 실전 적용 사례

반복되는 디자인 패턴을 필요한 설정값만 전달하면 완성되는 표준 가이드로 설계했습니다. 번거로운 수치 계산이나 중복 작성을 로직으로 대체하여 한줄의 코드로 일관성 있게 관리할 수 있도록 구현했습니다. 

/* 실제 프로젝트 _mixin.scss 소스코드의 일부입니다. */

@mixin pos-center($x: true, $y: true) {
  position: absolute;
  @if $x and $y {
    top: 50%; left: 50%;
    transform: translate(-50%, -50%);
  } @else if $x {
    left: 50%; transform: translateX(-50%);
  } @else if $y {
    top: 50%; transform: translateY(-50%);
  }
}

@mixin font-setup(
  $size,
  $family: map.get(var.$font-families, base),
  $weight: normal,
  $style: normal
) {
  font-size: #{$size};
  line-height: var.$line-height-base;
  font-weight: $weight;
  font-style: $style;
  font-family: $family;
}

@mixin respond($breakpoint) {
  @media (max-width: map.get(var.$breakpoints, $breakpoint)) {
    @content;
  }
}

/* -------------------------------------------------------- */

.title { @include mix.font-setup(32px, $weight: bold); }
.banner-img { @include mix.pos-center($y: false); }
@include mix.respond(md) { .container { width: 100%; } }

Map & List 실전 적용 사례

디자인 규격을 데이터 구조로 정의하고 이를 루프 안에서 자동으로 생성하는 시스템을 구축했습니다. 개별 클래스를 일일이 작성하는 번거로움을 없애고 데이터 수정만으로 전체 스타일을 유연하게 확장할 수 있는 구조를 완성했습니다. 

/* 실제 프로젝트 _gallery.scss 소스코드의 일부입니다. */

$articles: (
  "1": (width: 700px, height: 400px, bg: "700x400.png", inner: ("MerryChristmas")),
  "5-1": (width: 490px, height: 240px, bg: "490x240-1.png", inner: ("Programmer")),
  "7": (
    width: 1000px, height: 371px, bg: "1000x371.png",
    inner: ("Yours"), inner-size: (686px, 60px),
    pos-center: true, text-shadow: true
  )
);

@each $key, $props in $articles {
  .article--#{$key} {
    width: map.get($props, width);
    height: map.get($props, height);
    float: left; position: relative;

    @if map.has-key($props, bg) {
      background-image: url(../img/#{map.get($props, bg)});
    }

    @if map.has-key($props, inner) {
      @each $inner-name in map.get($props, inner) {
        .#{$inner-name} {
          position: absolute;

          @if map.has-key($props, inner-size) {
            $size: map.get($props, inner-size);
            width: list.nth($size, 1);
            height: list.nth($size, 2);
          }

          @if map.get($props, pos-center) { @include mix.pos-center(); }

          @if $key == "5-1" and $inner-name == "Programmer" {
            top: 160px; width: 300px;
            @include mix.pos-center($y: false);
          }
        }
      }
    }
  }
}

비교 분석

일반적인 CSS 방식이 모든 상황에 맞춰 중복된 코드를 여러번 복사해서 붙여넣어야 했다면 이번 설계에는 매개변수와 조건부 로직을 결합하여 상황에 맞춰 스타일을 결정하는 도구를 만들었습니다. 복잡한 계산 없이 한 줄의 호출만으로 디자인을 완성할 수 있었습니다. 이는 수동 작업의 한계를 로직으로 해결하여 나중에 디자인이 바뀌어도 도구 하나만 수정하면 전체가 한 번에 바뀌는 편리한 관리 환경을 만들어줍니다.

스타일을 클래스마다 일일이 수동으로 관리하던 방식에서 벗어나 모든 디자인 수치를 map과 list구조의 데이터로 정리했습니다. 단순히 값을 저장하는 CSS 변수의 기능을 넘어 보간법(#{})과 map.get, list.nth 함수를 활용해 데이터 명단만으로 스타일을 자동 생성하는 시스템을 구현했습니다. 결과적으로 수백 줄의 코드를 직접 수정해야 했던 방식과 달리 데이터를 추가하거나 수정하면 전체 화면의 스타일을 자유롭게 조절할 수 있는 유연한 구조를 완성했습니다.

주요 학습 포인트

반복되는 디자인 패턴을 단순히 복사하는 것이 아니라 이를 분석하고 @mixin과 조건부 로직으로 깔끔하게 정리하는 법을 익혔습니다. 이를 통해 작업 속도를 높이는 것은 물론 누구나 한 줄의 코드로 일관된 결과물을 낼 수 있는 사용하기 쉬운 도구를 만드는 역량을 키웠습니다.

스타일을 개별적인 코드의 나열이 아닌 관리 가능한 데이터 구조로 바라보는 시야를 갖게 되었습니다. 디자인 규격을 체계적으로 정리하고 이를 자동화 시스템과 연결함으로써 프로젝트의 규모가 커져도 데이터 수정만으로 전체 스타일을 제어할 수 있는 효율적인 관리 방식을 제 것으로 만들었습니다.

당장 작성하기 편한 코드보다 나중에 수정하기 좋은 구조가 좋은 설계라는 것을 깨달았습니다. 코드 간의 의존성을 줄이고 확장성을 고려한 설계를 통해 서비스의 변화나 디자인 수정 요청에도 빠르고 유연하게 대응할 수 있는 유지보수 감각을 기를 수 있었습니다.

SCSS @use & @forward

네임스페이스를 활용한 독립적 모듈 설계와 안전한 파일 통합 구조

소개

스타일 시트가 커질수록 변수가 충돌하거나 코드가 중복 로드되는 전역 오염 문제를 해결해야 했습니다. 단순히 파일을 합치는 과거의 @import 방식을 넘어 현대적인 @use와 @forward 시스템을 도입하여 각 스타일이 서로 간섭하지 않는 독립적인 모듈 구조를 설계했습니다.

모듈마다 고유한 네임스페이스를 부여해 변수 출처를 명확히 하고 _index.scss와 @forward를 활용해 여러 파일을 하나의 통로로 통합했습니다. 이를 통해 복잡한 경로 추적 없이 단 하나의 호출만으로 프로젝트 전체 스타일을 안전하게 제어할 수 있는 구조를 구현했습니다.

@forward 실전 적용 사례

디자인 자원을 성격에 따라 폴더별로 분류하고 각 폴더의 _index.scss에서 @forward를 통해 하위 파일들을 하나의 모듈로 통합했습니다. 이를 통해 외부에서는 수많은 개별 파일의 상세 경로를 일일이 추적할 필요 없이 폴더 이름만으로 모든 자원을 참조할 수 있는 구조입니다. 

/* abstracts/_index.scss */

@forward 'variables';
@forward 'mixin';

/* base/_index.scss */

@forward 'reset';
@forward 'body';

/* layout/_index.scss */

@forward 'header';
@forward 'footer';
@forward 'wrapper';

/* pages/_index.scss */

@forward 'home';
@forward 'select'; 

/* -------------------------------------------------------- */

/* main.scss */

@use 'abstracts';
@use 'base';
@use 'layout';
@use 'pages';
@use 'components/button';
@use 'utilities/utilities';

@use 실전 적용 사례

@use와 네임스페이스를 활용해 스타일의 출처를 명확히 하고 기존 @import 방식의 전역 오염 및 이름 충돌 문제를 근본적으로 해결했습니다. 파일 상단에 의존성을 명시함으로써 대규모 프로젝트에서도 안전하고 투명한 모듈 관리가 가능하도록 설계했습니다. 

/* layout/_header.scss */

@use "sass:map";
@use "../abstracts" as abs;

%header-item-base {
  height: 100%;
  padding: 10px;
  @include abs.flex-col;
}

.header {
  height: 100%;
  border-right: 2px solid map.get(abs.$colors, "white");
  @include abs.flex-col;

  &__logo {
    @extend %header-item-base;

    @include abs.font-setup(
      map.get(abs.$font-sizes, "logo"),
      map.get(abs.$font-families, "logo"),
      bold,
      italic
    );
    color: map.get(abs.$colors, "white");
  }
}

비교 분석

기존의 @import 방식은 모든 변수와 믹스인이 전역으로 공유되어 의도치 않은 스타일 중첩과 이름 충돌이 발생하는 전역 오염의 한계가 있었습니다. 특히 수많은 파일 중에서 특정 변수의 출처를 파악하기 어렵고 동일한 파일을 여러 번 호출할 경우 중복 컴파일로 인해 빌드 효율이 저하되는 단점을 가지고 있었습니다.

이를 해결하기 위해 @use와 @forward를 조합한 현대적인 모듈 시스템을 도입했습니다. 각 폴더를 하나의 꾸러미로 묶고 사용할 때는 네임스페이스를 통해 출처를 명확히 표시했습니다. 덕분에 이름이 겹칠 걱정 없이 안전하게 코드를 짤 수 있고 수정이 필요할 때도 해당 파일만 고치면 되어 유지보수가 훨씬 간편하고 정확해졌습니다.

주요 학습 포인트

수많은 스타일 파일들이 흩어지지 않도록 단일 진입점(_index.scss)을 구축하며 프로젝트의 전체적인 질서를 잡는 법을 익혔습니다. 폴더별로 기능을 묶어 외부에 공개하는 방식을 통해 호출하는 쪽에서는 내부 구조를 몰라도 필요한 자원을 쉽게 찾아 쓸 수 있는 모듈 시스템을 경험했습니다. 이는 복잡한 대규모 프로젝트에서도 스타일의 흐름을 한눈에 파악하고 제어할 수 있는 기초가 되었습니다.

변수나 믹스인을 사용할 때 출처를 명시하는 네임스페이스 활용 습관을 통해 코드 한 줄이 미치는 영향을 스스로 통제할 수 있게 되었습니다. 단순히 스타일을 입히는 단계를 넘어 하나의 코드가 의도치 않게 다른 곳에 영향을 주지 않도록 시스템적인 규칙으로 해결하며 안전한 코드를 고민하게 되었습니다. 결과적으로 수정이 필요할 때 망설임 없이 필요한 파일만 관리할 수 있는 지속 가능한 개발 흐름을 완성했습니다.

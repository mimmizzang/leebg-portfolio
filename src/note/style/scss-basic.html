SCSS Variables & Nesting

반복되는 스타일 상수를 관리하는 변수와 HTML 구조를 반영한 중첩 문법

소개

프로젝트의 규모가 커질수록 색상값 하나를 바꾸기 위해 수십 개의 CSS 파일을 뒤지거나 복잡하게 얽힌 선택자 때문에 스타일 우선순위가 꼬이는 문제는 개발의 효율성을 저하시킵니다.

최근 Native CSS에서도 변수와 중첩 문법이 도입되고 있으나 브라우저 호환성에 구애받지 않는 안정성과 강력한 산술 연산 기능을 갖춘 SCSS를 선택했습니다. 이를 통해 프로젝트 초기부터 확장 가능하고 체계적인 디자인 시스템의 기반을 구축하고자 했습니다.

문법 대조 분석

동일한 컴포넌트를 구현할 때 발생하는 코드의 중복을 제거하고 계층 구조를 반영한 중첩 문법으로 가독성을 높였습니다.

CSS
.card {
  width: 100%;
  max-width: 384px;
  background-color: #1e293b;
  padding: 1.5rem;
  border-radius: 1rem;
}

.card__title {
  font-size: 1.125rem;
  font-weight: 700;
  margin-bottom: 0.5rem;
}

.card__btn {
  width: 100%;
  background-color: #4f46e5;
  padding: 0.75rem 1rem;
}

.card__btn:hover {
  background-color: #6366f1;
}
SCSS
$card-bg: #1e293b;
$primary: #4f46e5;
$primary-light: #6366f1;

.card {
  width: 100%;
  max-width: 384px;
  background-color: $card-bg;
  padding: 1.5rem;
  border-radius: 1rem;

  &__title {
    font-size: 1.125rem;
    font-weight: 700;
    margin-bottom: 0.5rem;
  }

  &__btn {
    width: 100%;
    background-color: $primary;
    padding: 0.75rem 1rem;

    &:hover {
      background-color: $primary-light;
    }
  }
}

실전 적용 사례

Variables

map.get과 전역 변수를 활용하여 컬러와 폰트 규격을 체계적으로 관리했습니다.

Nesting

HTML의 계층 구조를 CSS에 그대로 투영하여 선택자 중복을 제거하고 가독성을 높였습니다.

& Selector

부모 참조 선택자를 통해 BEM 네이밍(__item, &-text)을 효율적으로 구현했습니다.

Responsive

미디어 쿼리를 컴포넌트 내부에 중첩하여 기기별 스타일 대응을 관리했습니다. 

/* 실제 프로젝트 _home.scss 소스코드의 일부입니다. */

@use "sass:map";
@use "../abstracts/variables" as var;
@use "../abstracts/mixin" as mix;

.main {
  height: 100%;

  &__item {
    @include mix.flex-col;
    position: relative;
    transition: all 0.6s;

    &-text {
      color: map.get(var.$colors, "white");
      
      p {
        @include mix.font-setup(map.get(var.$font-sizes, p));
      }
    }

    &:hover {
      opacity: 1;
      .main__item-overlay { transform: translateX(0); }
    }

    @include mix.respond(xl) {
      padding: 50px 30px;
      
      &-text p { font-size: 0.9em; }
    }

    @include mix.respond(md) {
      flex-basis: 45%;
      min-height: 500px;
    }
  }
}

비교 분석

Native CSS에도 변수와 중첩 문법이 도입되고 있지만 Variables($)와 Sass Map을 활용한 시스템은 더욱 강력한 제어력을 제공합니다. 단순히 값을 저장하는 것을 넘어 map.get() 함수를 통한 복잡한 산술 연산과 디자인 시스템의 규격을 중앙에서 체계적으로 관리할 수 있기 때문입니다. 이는 대규모 프로젝트에서도 디자인의 일관성을 유지하는 기반이 됩니다.

Nesting은 단순한 시각적 계층화를 넘어 부모 참조 선택자(&)와의 결합을 통해 그 진가를 발휘합니다. Native CSS의 중첩보다 직관적인 BEM 네이밍 구현을 지원하며 특정 컴포넌트의 스타일을 한군데에 모아 관리할 수 있도록 돕습니다. 결과적으로 브라우저 호환성 걱정 없이 구조적 이점을 누릴 수 있으며 클래스명 변경에도 유연하게 대응하는 탄탄한 코드 구조를 완성합니다.

주요 학습 포인트

초기 설계 단계에서 공통 요소를 추출해 변수로 구조화하는 과정은 단순히 코드를 작성하는 것보다 많은 고민이 필요했습니다. 하지만 이를 통해 디자인 가이드라인을 코드화하는 법을 익혔고 컬러나 폰트 규격이 바뀌더라도 변수 수정만으로 프로젝트 전체를 제어하는 효율성을 체감했습니다. 결과적으로 불필요한 반복 작업을 줄이고 프로젝트 규모가 커져도 스타일의 통일성을 유지할 수 있는 기반이 되었습니다.

Nesting과 BEM을 결합하여 HTML 구조가 한눈에 보이는 직관적인 스타일 시트를 작성했습니다. 이는 단순히 코드를 중첩하는 것을 넘어 스타일의 소속 관계를 즉각적으로 파악할 수 있게 돕는 읽기 좋은 코드에 대한 기준을 세우는 계기가 되었습니다.

Tailwind CSS vs Vanilla CSS

클래스 네이밍 스트레스에서 벗어나 오직 디자인과 구조에만 집중하는 시간

소개

정보량이 많고 구조가 복잡한 프로젝트일수록 CSS 파일의 규모는 커지기 마련입니다. 특히 각 요소의 역할을 정의하기 위해 복잡한 클래스명을 설계하고 중복되지 않도록 하는 과정은 불편할 수 있다고 생각했습니다.

저는 프로젝트에서 Utility-first 철학을 가진 Tailwind CSS를 도입했습니다. 이를 통해 별도의 이름을 고민하거나 CSS 파일을 오가는 번거로움 없이 HTML 내부에서 즉시 스타일을 완성하는 효율적인 작업을 경험했습니다. 단순히 속도가 빠른 코딩을 넘어 일관된 디자인 가이드를 유지하며 유지 보수가 용이한 인터페이스를 만들고자 했습니다.

예제 화면

프로젝트에 사용했던 Tailwind CSS 데모가 준비되어 있습니다.

전통적인 방식 (Vanilla CSS)

기존 방식은 스타일을 정의하기 위해 HTML과 CSS 파일을 끊임없이 오가야 하며 반응형 대응을 위해 코드의 중복과 커짐이 발생합니다. 

<div class="container">
  <div class="card">
    <div class="icon-box">
      <i class="fa-solid fa-flag"></i>
    </div>
    <h3 class="card-title">Card Component</h3>
    <p class="card-desc">
      이 화면은 Vanilla CSS와 Tailwind 두 방식 모두로 동일하게 구현될 수 있습니다.
    </p>
    <button class="card-btn">
      Button
    </button>
  </div>
</div>

유틸리티 우선 방식 (Tailwind CSS)

Tailwind CSS는 별도의 클래스 설계 없이 유틸리티 클래스만으로 스타일을 완성합니다. HTML 내부에서 레이아웃과 반응형 처리를 동시에 끝낼 수 있습니다. 

<div class="flex w-full flex-col items-center justify-center 
            gap-12 md:flex-row">
  <div class="w-full max-w-sm rounded-2xl border border-slate-700 
              bg-slate-800 p-6 shadow-xl">
    <div class="mb-4 flex h-10 w-10 items-center justify-center 
                rounded-lg bg-indigo-500">
      <i class="fa-solid fa-flag text-white"></i>
    </div>
    <h3 class="mb-2 text-lg font-bold">Card Component</h3>
    <p class="mb-6 text-sm leading-relaxed text-slate-400">
      이 화면은 Vanilla CSS와 Tailwind 두 방식 모두로 동일하게 구현될 수 있습니다.
    </p>
    <button class="w-full rounded-xl bg-indigo-600 px-4 py-3 text-sm 
            font-semibold text-white transition-all duration-200 
            hover:bg-indigo-500 active:scale-95"
    >
      Button
    </button>
  </div>
</div>

비교 분석

전통적인 방식인 Vanilla CSS는 스타일 시트와 HTML 사이를 끊임없이 오가며 클래스명을 고민해야 하고 단순한 레이아웃 변경이나 상태 변화를 위해서도 미디어 쿼리와 셀렉터를 일일이 선언해야 하는 번거로움이 있습니다.

반면 Tailwind CSS의 Utility-first 방식은 별도의 클래스 설계 없이 HTML 내부에서 레이아웃과 반응형 처리를 동시에 끝낼 수 있게 해줍니다. active:scale-95나 hover:bg-indigo-500처럼 상태 변화를 클래스 한 단어로 제어할 수 있다는 점은 스타일 정의가 HTML 구조 안에서 한눈에 파악할 수 있어 효율적이었습니다.

화면 전체의 구조를 잡을때도 Tailwind는 md:flex-row와 같은 접두어 하나로 화면 크기에 따른 레이아웃 변화를 HTML 안에서 직접 해결합니다. 이러한 방식은 스타일 정의에 들어가는 수고를 줄여준다고 생각합니다.

주요 학습 포인트

Tailwind를 사용하며 느낀 점은 모든 스타일을 무에서 유로 창조할 필요성이 줄었다는 것이었습니다. 이전에는 색상 코드 하나, 여백 1px까지 매번 고민해야 했지만 Tailwind가 제공하는 정의된 수치 시스템 안에서 코드를 짜는 것만으로도 충분히 일관성 있고 완성도 높은 결과물을 만들 수 있었습니다. 임의의 수치가 필요한 순간에는 h-[550px]처럼 대괄호를 활용하거나 theme 설정을 통해 확장할 수 있다는 점이 매력적이었습니다.

이전에는 웹 화면을 먼저 만들고 미디어 쿼리로 모바일을 맞추는 방식이 익숙했습니다. 하지만 Tailwind는 기본 클래스가 모바일을 타겟팅하고 md: lg: 같은 접두어를 붙여 큰 화면에 대응하는 방식을 지향합니다. 처음에는 어색했지만 모바일을 기준으로 뼈대를 잡고 확장해 나가는 방식이 오히려 코드의 중복을 줄이고 어떤 기기에서도 레이아웃이 깨지지 않게 만드는 데 훨씬 유리하다는 것을 경험했습니다.
